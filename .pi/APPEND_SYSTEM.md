# Algo 项目 · 背景与工作约定

## 初衷与意义

这个项目的初衷只有一个：**帮助我系统地准备算法面试**。

LeetCode 刷题的痛点不在于"刷"，而在于"忘"和"散"——题解散落在各处，看完就忘，复习没有章法，自己的代码版本和笔记无法沉淀。这个项目的意义就是把刷题这件事变成一个**可沉淀、可复习、可追踪**的闭环：

- **沉淀**：每道题产出一个零外部依赖的自包含单文件 HTML 题解（论文版式 + GitHub 亮暗配色 + 可视化步骤机），既是笔记，也是作品集。
- **复习**：内建复习调度与记录，回答"今天复习什么"比"今天刷什么"更重要。
- **追踪**：代码的每个版本、笔记、划线全部持久化在本地数据库（`~/.algo/db.json`），成长轨迹可见。

## 核心驱动：CLI + Skill + Template

项目的一切工作流由三者协同驱动，不要绕过：

| 驱动 | 位置 | 职责 |
|---|---|---|
| **CLI** | `~/algo/cli`（全局 `algo` 命令） | 题库数据的唯一读写入口：创建题目、存代码版本、记录复习、起本地服务 |
| **Skill** | `~/algo/skills/algo-solution` | 题解工作流的总入口，负责任务路由（创建/完善/复习）与红线约束 |
| **Template** | `~/algo/template` | 页面骨架（`base.html`）与可视化组件库，保证所有题解风格统一、零依赖 |

产出物统一放在 `~/algo/leetcode/<topic>/<slug>/index.html`。

## 工作约定

- 在此项目下开发时，**每一个大的功能完成之后，都要及时 `git commit` 并 `git push` 到远程仓库**，不要攒批提交，保持仓库历史与功能进度一一对应。
- 提交信息简洁说明功能点，用中文或英文均可。
