## 思路

**排序 + 固定一个数 + 双指针**（文档里说的「排序 + 三指针」）：

1. 先把数组升序排序。排序后每个三元组内部自然满足 `a <= b <= c`，同一个三元组的不同排列会被排成同一种形态，便于去重。
2. 枚举**最小的那个数** `nums[k]`（`k` 从小到大）。如果 `nums[k] > 0`，后面不可能再凑出和为 0，直接结束；如果 `nums[k] == nums[k - 1]`，说明这个「最小数」上一轮已经枚举过，跳过。
3. 在区间 `[k + 1, n - 1]` 上用左右指针 `i`、`j` 找两数之和等于 `-nums[k]`：
   - `sum < 0`：和太小，`++i`；
   - `sum > 0`：和太大，`--j`；
   - `sum == 0`：记录答案，然后跳过所有与 `nums[i]` / `nums[j]` 相同的值，再同时收缩。

**为什么对**：固定 `nums[k]` 后问题变成「有序数组里找两数之和 = `target`」，双指针的正确性来自单调性——和偏小只可能是左指针太小（右指针已经在最大位置），和偏大只可能是右指针太大，指针只会单向移动，所以不会漏掉任何一对。又因为排序后 `a <= b <= c`，每个合法三元组只有一种排列会被枚举到；再配合三处跳过相同值，结果既不重复也不遗漏。

## 复杂度

- 时间：O(n²)——排序 O(n log n)，外层枚举 `k` 是 O(n)，内层双指针是 O(n)
- 空间：O(1)（不算存放答案的空间；排序是原地排序）

## 关键点

- **先排序**：既是双指针的前提，也是去重的前提
- 三处都要去重：第一个数（`nums[k] == nums[k - 1]` 跳过）、第二个数、第三个数（找到答案后跳过相同值），漏掉任何一处都会产生重复三元组
- 剪枝 `nums[k] > 0` 时 `break`：最小的数都大于 0，和不可能为 0
- 内置库里的去重写法 `while (i < j && nums[i] == nums[++i])` 在 C++ 里容易写出越界，改成先判断再自增更稳
- 和为 0 的三元组可能为空，此时要输出一个空行，不要什么都不输出
- `n < 3` 时直接输出空行
- 三个数都在 `10^5` 量级，两两相加不会溢出 `int`，不用开 `long long`
