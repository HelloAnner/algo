## 思路

DFS + 回溯：维护一条当前路径 `path` 和一个剩余目标和 `remain`。

1. 进入节点时 `remain -= node.val`，并把 `node.val` 压入 `path`；
2. 如果该节点是**叶子**且 `remain == 0`，就把当前 `path` 拷贝一份存进答案；
3. 递归左右子树；
4. 离开节点时 `path.pop_back()`，把状态还原，交给兄弟分支继续使用。

和文档里 Java 解法的区别只在实现细节：Java 每次递归都 `new ArrayList<>(list)` 复制一份路径，这里改成「一份 `path` + 回溯」，每个节点只入栈出栈一次，省掉了每层的复制。

为什么必须等到叶子：题目要求路径从根一直延伸到叶子，和等于目标值的内部节点不能算答案。节点值可以是负数，所以不能靠「`remain` 小于 0」剪枝，只能老老实实搜到底。

## 复杂度

- 时间：O(n^2)。DFS 本身是 O(n)，但答案里每条路径最长 O(n)，把它们拷进结果的总代价是「所有答案路径长度之和」，最坏是链状树上的 O(n^2)（输出规模本身也有这么大）
- 空间：O(h)。`path` 和递归栈都只占树高 h；结果数组不计入

## 关键点

- 记录答案时要**拷贝** `path`，不能存引用——回溯会把内容改掉
- 只有「叶子且 `remain == 0`」才记录，和等于目标的内部节点不算
- 空树返回空结果，输出 `0`；注意不要对空指针解引用
- 回溯要成对：`path.push_back` 对应 `path.pop_back`；`remain` 用值传递，天然还原
- 节点值可以是负数，不能剪枝
- 输出时先打印条数，再逐行打印路径，行内用空格分隔、行尾不留多余空格
