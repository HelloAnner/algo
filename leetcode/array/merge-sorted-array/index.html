合并两个有序数组

merge-sorted-array — 逆向双指针：从后往前填，谁大谁落位

简单 数组 双指针

01题目

给你两个按非递减顺序排列的整数数组 nums1 和 nums2，另有两个整数 m 和 n 分别表示两数组中的元素数目。请你把 nums2 合并到 nums1 中，使合并后的数组同样按非递减顺序排列。

nums1 的长度为 m + n，前 m 个是有效元素，后 n 个是 0（预留空位）。最终结果存在 nums1 里，原地修改。

输入：nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3 输出：[1,2,2,3,5,6]
核心洞察 从前往后填会覆盖 nums1 还没处理的元素；从后往前填，空位就在身后——每次把两个数组当前最大值放到尾部，谁大谁落位，O(1) 空间原地完成。

02思路演进

第一反应：把 nums2 拷进 nums1 尾部再整体排序。一行能写完，但 O((m+n)log(m+n))，完全浪费了"两个数组各自有序"这个条件。

利用有序性：经典归并——两个指针分别扫 nums1、nums2，谁小取谁。但正向归并需要额外数组暂存结果，否则边取边写会覆盖 nums1 中还没比较的元素。O(m+n) 空间。

关键反转：nums1 尾部有 n 个空位——空位在后面，那就从后往前填。两个指针指向有效元素的末尾，再一个写指针指向 nums1 尾部，谁大写谁。覆盖的都是空位或已落位的元素，绝对安全。O(1) 空间。

05代码实现

def merge(nums1, m, nums2, n):
    # 最直白：拷过去再排，浪费有序性
    nums1[m:] = nums2
    nums1.sort()
def merge(nums1, m, nums2, n):
    # 经典归并：正向双指针 + 暂存数组，O(m+n) 空间
    tmp = nums1[:m]
    p1 = p2 = 0
    for p in range(m + n):
        if p2 >= n or (p1 < m and tmp[p1] <= nums2[p2]):
            nums1[p] = tmp[p1]; p1 += 1
        else:
            nums1[p] = nums2[p2]; p2 += 1
def merge(nums1, m, nums2, n):
    # 从后往前：谁大谁落位，O(m+n) 时间 / O(1) 空间
    p1, p2, p = m - 1, n - 1, m + n - 1
    while p2 >= 0:  # nums2 用完就结束（nums1 剩的本来就在位）
        if p1 >= 0 and nums1[p1] > nums2[p2]:
            nums1[p] = nums1[p1]; p1 -= 1
        else:
            nums1[p] = nums2[p2]; p2 -= 1
        p -= 1

循环条件只写 p2 >= 0 就够了：nums2 先用完时 nums1 剩余前缀天然有序且已在正确位置；nums1 先用完时把 nums2 剩余挨个拷入即可，循环自然覆盖。少一个分支，少一类 bug。

06复杂度对比

解法时间空间说明
合并后排序O((m+n)log(m+n))O(log(m+n))浪费有序性，排序栈开销
正向归并O(m+n)O(m)需暂存 nums1 有效段
逆向双指针O(m+n)O(1)空位在后 → 从后填，原地

07边界、坑与变体

  • n = 0：循环一次都不进，nums1 原样返回，天然正确。
  • m = 0：nums1 全是空位，p1 = -1，直接挨个拷 nums2，也正确。
  • 坑：正向写时总想"先把 nums1 元素挪走"——逆向写法就是为了避开这个念头。
  • 变体 → LC 21（合并两个有序链表）：同样的归并思想，链表天然适合正向操作（改指针不覆盖数据）。
  • 变体 → LC 23（合并 K 个有序链表）：归并的推广，两路归并升 K 路，用堆或分治。
