# 链表相交 · 解法

## 思路

双指针「走对方走过的路」，对应文档里的 Java 解法。

设两条链表在交点 C 处汇合（不相交时可以认为公共部分长度为 0）：

- 指针 p 从 A 的表头出发，走完 A 之后接着从 B 的表头继续走；
- 指针 q 从 B 的表头出发，走完 B 之后接着从 A 的表头继续走。

两个指针每轮各前进一格。p 走到交点时走过的长度是「A 的独有部分 + 公共部分 + B 的独有部分」，q 走到交点时走过的长度是「B 的独有部分 + 公共部分 + A 的独有部分」，两者完全相等，所以两个指针一定在交点相遇（p == q）。

如果两个链表不相交，两个指针会各自走完 A + B（共 n + m 步），然后**同时变成 nullptr**，循环条件 p != q 不再成立，返回 nullptr。

## 复杂度

- 时间：O(n + m)，两个指针合计最多走 2(n + m) 步
- 空间：O(1)，只用两个指针（ACM 判题时为了建链表本身要开节点数组，那属于输入数据，不计入算法的额外空间）

## 关键点

- 比较的必须是**指针本身**而不是 val：值相同不代表是同一个节点，写成 p->val == q->val 就错了
- 切换链表要写成 `p = p ? p->next : headB;`，先判空再取 next，不能先解引用
- 不相交时不会死循环：两个指针最后同时变成 null，循环自然结束
- 建链表时必须让公共部分真正共享同一个节点对象（C++ 里用 `vector<Node>` 存节点再取地址），否则「引用相交」就无从谈起；B 的公共部分不是新建节点，而是直接指向 A 的对应节点
- 其他解法：先各求一次链表长度、让长的先走长度差，同样 O(1) 空间；或者用哈希表存 A 的节点再遍历 B，时间 O(n + m) 但空间 O(n)，不满足题目的空间要求
