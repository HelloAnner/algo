题目：找出重复元素
链接：
难度：中等

[题目描述]

有 n 个正整数，取值范围是 0 ~ 42 亿（即 0 <= a[i] <= 4200000000）。数据保证每个数字要么出现 1 次，要么出现 2 次。

请找出所有恰好出现 2 次的数字。

原题考的是空间复杂度：直接用哈希表虽然能过，但不是考点；正确做法是位图（bitmap）——用 2 bit 记录每个数字出现的次数，再按位图顺序输出。

位图的下标就是数值本身（或平移后的数值），所以从头扫一遍位图，输出的就是升序结果：

    数值    0      1      2      3      4      5    ...   42亿
          +------+------+------+------+------+------+-----+
    出现  |  0   |  1   |  2   |  2   |  1   |  1   | ... |
          +------+------+------+------+------+------+-----+
                           ^      ^
                        输出 2  输出 3（按位图顺序即升序）

    示例 1：a = 1 2 3 2 4 5 3  ->  输出 2、3

[输入格式]

第一行一个整数 n。
第二行 n 个整数 a[0..n-1]，用空格分隔（可以跨多行）。

[输出格式]

按升序输出所有出现 2 次的数字，每个数字占一行。
如果不存在出现 2 次的数字，输出一行 -1。

[示例 1]
输入：
7
1 2 3 2 4 5 3
输出：
2
3
解释：2 和 3 各出现 2 次，按升序逐行输出。

[示例 2]
输入：
5
100 200 300 400 500
输出：
-1
解释：每个数字都只出现 1 次，没有出现 2 次的数字，输出 -1。

[示例 3]
输入：
4
4200000000 4199999999 4200000000 4199999999
输出：
4199999999
4200000000
解释：4200000000 超过了 int 的范围（int 最大约 21.47 亿），必须用 64 位整数保存；位图按下标整体平移最小值后只覆盖 [min, max] 这一段。

[数据范围]

- 1 <= n <= 2 * 10^5
- 0 <= a[i] <= 4200000000（超过 int 范围，要用 long long / unsigned int）
- 每个数字出现 1 次或 2 次
- 本地数据额外保证 max - min <= 2 * 10^7，这样 2 bit/数字的位图约 5 MB；真实场景下 42 亿的取值范围需要约 1 GB 位图，通常配合「先求 min 平移下标」或分块处理（文档里的 Java 代码正是先求 min/max 再平移）

[备注]

- 来源：非 LeetCode 题，来自《手撕字节跳动面试时出现过的算法题》第 14 节「找出重复元素」
- 文档中的 Java 解法用 byte[] 每个 bit 记录「是否出现过」，第二次遇到就打印；这里为了严格判定「恰好 2 次」，改成每个数字 2 bit 的计数器（计数到 3 饱和，出现 3 次及以上的数字不会被误判成「恰好 2 次」）
