# 找出重复元素 · 解法

## 思路

**位图 + 下标平移（2 bit 计数）**，对应文档里 Java 版的位图思路：

1. 先扫一遍数据求出最小值 min 和最大值 max。42 亿的取值范围直接开位图太大，把下标整体平移 min 之后，位图只需要覆盖 [min, max] 这一段。
2. 开一个位图，**每个数字占 2 bit**，记录它出现过的次数（0 / 1 / 2 / 3，计数到 3 就饱和，3 表示出现 3 次及以上）。
   - 下标 `i = a[k] - min`；
   - 所在字节 `byte = i >> 2`，字节内偏移 `shift = (i & 3) * 2`；
   - 计数 `cnt = (bitmap[byte] >> shift) & 3`：只要 cnt < 3 就加一（0→1→2→3），加到 3 之后保持不变。
3. 位图的下标天然有序，从头到尾扫一遍，凡是计数等于 2 的位置，其对应数字就是 min + i，直接按升序输出。
4. 一个都没有时输出 -1。

如果像文档的 Java 代码那样每个数字只用 1 bit（只记「出现过没有」），第二次遇到时打印即可，但那样无法区分「出现 2 次」和「出现更多次」；本题用 2 bit 更严谨，也能顺便省掉一次排序。

## 复杂度

- 时间：O(n + (max - min))，一遍读入统计、一遍扫位图输出
- 空间：O((max - min) / 4) 字节，即每个数字 2 bit（本题规模约 5 MB）；把输入全部读进数组还要 O(n)，也可以边读边统计（但求 min/max 需要先读一遍或分块）

## 关键点

- 数值范围到 42 亿，**超过 int（约 21.47 亿）**，必须用 `long long`；位图下标要用 64 位算完再转 `size_t`
- 下标一定要平移 min，否则位图长度按 max 开，既慢又费内存（文档 Java 代码里的 `num / 8 - min / 8` 就是在做平移）
- 2 bit 计数要用掩码取：`(bitmap[byte] >> shift) & 3`，不能写成只适合 1 bit 的 `(bitmap[byte] & (1 << k)) > 0`
- 按位图顺序输出天然升序，不需要再 sort；若改用哈希表统计就得额外排序
- 空结果输出 -1，注意别输出空行
- 其他解法：排序后扫一遍（O(n log n)、除输入外空间 O(1)），或哈希表/哈希集合（O(n) 时间但空间远大于位图）
