## 思路

滑动窗口（双指针 + 哈希）：维护窗口 `[left, right]`，保证窗口内的字符互不重复。

- `right` 从 0 扫到 `n-1`，每次把 `s[right]` 纳入窗口；
- 若 `s[right]` 上一次出现的位置满足 `last[c] >= left`，说明窗口内已经有它了，把 `left` 一步跳到 `last[c] + 1`；
- 用 `right - left + 1` 更新答案，再令 `last[s[right]] = right`。

为什么对：右端点固定为 `right` 时，左端点最小只能取到 `last[s[right]] + 1`（再往左窗口里必然含有两个相同字符），所以这一步跳过去不会漏掉任何以 `right` 结尾的合法窗口；`left`、`right` 都只前进不后退，总移动量 O(n)。

文档里的 Java 解法用 `set` 配合 `while (set.contains(...))` 一个个删左指针，本质相同，但那种写法每个字符最多被加/删一次，这里用 `last` 数组一步定位，少了一层循环。

## 复杂度

- 时间：O(n)，`left` 和 `right` 各自最多走 n 步
- 空间：O(1)，长度为 128 的数组记录每个 ASCII 字符最后出现的位置

## 关键点

- 判断条件是 `last[c] >= left`，不能写成 `last[c] != -1`：字符上次出现在窗口左边界左边时，窗口内其实没有它，此时不该移动 `left`
- `left` 只增不减，不要写成 `left = last[c] + 1` 而不加判断，否则会把左边界往回拽
- 空串要输出 0；用 `getline` 读入可以正确处理空行
- 长度 4 万，`O(n^2)` 地枚举每个起点会超时
- 用 `unsigned char` 作下标，避免负数字节访问数组越界
