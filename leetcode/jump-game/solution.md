## 思路

贪心维护「最远可达下标」`reach`：

- 初始 `reach = 0`；
- 从左往右扫描下标 `i`，只要 `i <= reach`（说明 `i` 可达），就用 `i + nums[i]` 更新 `reach`；
- 一旦 `reach >= n - 1`，最后一个下标可达，输出 `true`；
- 如果某个 `i > reach`，说明中间出现断档，`i` 及其后面都不可达，输出 `false`。

正确性：扫描到 `i` 时，`reach` 恰好是「前 `i` 个位置能跳到的最远下标」。若存在某个可达位置能越过断点，它一定已经被扫描过并把 `reach` 推到了断点之后；因此 `i > reach` 时就真的走不动了，`reach` 永远不会漏掉可行解。

文档里给的另一种思路是「找出所有 0，检查每个 0 前面有没有元素能跨过它」，本质相同，但要额外处理末尾的 0；贪心写法更短，也不会退化。

## 复杂度

- 时间：O(n)，每个下标只访问一次
- 空间：O(1)（不计读入的数组）

## 关键点

- 判断条件是 `i <= reach` 而不是 `i < reach`：站在当前位置本身是允许的
- `n == 1` 时天然可达，循环里 `reach >= n - 1` 会直接输出 `true`
- `nums[i]` 可能为 0，此时 `reach` 不增长，靠 `i > reach` 提前退出，不能写成死循环
- 输出的是 `true` / `false` 字符串，不是 `1` / `0`
- `i + nums[i]` 在 `n = 3 * 10^4`、`nums[i] = 10^5` 时最大约 1.3 * 10^5，`int` 足够
