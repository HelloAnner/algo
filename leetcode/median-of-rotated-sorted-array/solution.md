## 思路

旋转只是把有序序列切成两段交换了位置，所以「排序后的第 k 个元素」和「原数组下标」之间只差一个固定的偏移量：

1. 二分找出**最小元素所在的下标** `rot`，它同时也是排序后第一个元素在原数组中的位置：
   - 取 `mid`，若 `nums[mid] > nums[hi]`，说明最小值一定在 `mid` 右边，令 `lo = mid + 1`；
   - 否则最小值在 `mid` 或它左边，令 `hi = mid`；
   - 循环结束（`lo == hi`）时 `lo` 就是 `rot`。数组没旋转时这个二分自然收敛到 `rot = 0`。
2. 有了 `rot`，排序后第 `k` 小（从 0 开始）的元素就是 `nums[(rot + k) % n]`：
   - 奇数个元素：答案是 `k = n / 2` 处的值；
   - 偶数个元素：答案是 `k = n / 2 - 1` 与 `k = n / 2` 两处的平均值。

为什么对：旋转等价于把有序序列从 `rot` 处切开再交换两段，于是「排序后的第 k 个」在原数组中恰好落在下标 `(rot + k) mod n`，是一一对应；再按中位数的定义取中间的一个或两个元素即可。文档里 Java 解法数「被搬到后边的元素个数」再取模，是同一个思路，但它把 `rot` 定义成「第一个下降点的下标」，数组**没有旋转**时会退化成 `n-1` 导致答案错位；本实现用「最小元素下标」定义 `rot`，两种情况都正确。

## 复杂度

- 时间：O(n) 读入 + O(log n) 定位与取值（若数组已经在内存里，求中位数只要 O(log n)）
- 空间：O(1) 额外空间（存输入数组本身是 O(n)）

## 关键点

- `rot` 要定义成「最小元素的下标」而不是「第一个下降点的下标」，否则未旋转的数组会算错偏移
- 二分的比较对象是 `nums[hi]` 而不是 `nums[lo]` / `nums[0]`，收缩方向别写反：`nums[mid] > nums[hi]` 时最小値在右半段
- 偶数个元素时两个中间值相加可能超出 `int`（元素可达 `±10^9`），要用 `long long` 保存
- 平均值是 `x.5` 时输出一位小数：C++ 里 `-7 / 2 == -3`（向零取整），所以先输出 `sum / 2` 再补 `.5`，正负数都对
- 边界情况：`n == 1` 时中位数就是唯一的元素；旋转量为 0 时也要走通
