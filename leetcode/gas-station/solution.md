## 思路

一次遍历的贪心：

- `total`：所有 `gas[i] - cost[i]` 的总和。如果 `total < 0`，油的总量都不够跑一圈，直接返回 `-1`；
- `curr`：从当前候选起点出发、开到当前位置剩下的油；
- `start`：当前候选起点的下标。

遍历时 `curr += gas[i] - cost[i]`。一旦 `curr < 0`，说明从 `start` 到 `i` 之间的任何一个站出发都到不了 `i + 1`（因为从中间出发剩下的油只会更少），于是把起点改成 `i + 1`，并把 `curr` 清零重新累计。

## 复杂度

- 时间：O(n)，一趟扫描
- 空间：O(1)

## 关键点

- 无解的充要条件是总油量小于总消耗：`total < 0`
- `curr < 0` 时，起点可以直接跳到 `i + 1`，不需要回退（这是省掉 O(n^2) 暴力的关键）
- 起点可能停在 `n`，但此时一定有 `total < 0`，所以最终用 `total >= 0 ? start : -1` 收口
- `gas[i] - cost[i]` 可能累加得比较大，用 `long long` 更稳
- 有解时答案唯一，不需要考虑多个起点
