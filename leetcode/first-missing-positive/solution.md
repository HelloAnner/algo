## 思路

**原地哈希（置换法）**。关键观察：长度为 `n` 的数组，缺失的最小正整数一定在 `[1, n + 1]` 之间，所以只需要关心值落在 `[1, n]` 内的元素。

把这 `n` 个「坑位」看成哈希桶：让值 `v` 待在**下标 `v - 1`** 上。做法是扫一遍数组，只要当前位置的值 `v` 满足 `1 <= v <= n` 且 `nums[v - 1] != v`（它的目标位置还没被正确的值占住），就把 `nums[i]` 和 `nums[v - 1]` 交换，直到当前位置的值不需要再动为止。

交换结束后再扫一遍：第一个满足 `nums[i] != i + 1` 的下标 `i`，说明值 `i + 1` 没出现过，答案就是 `i + 1`；如果所有位置都满足，说明 `1..n` 全部出现，答案是 `n + 1`。

**为什么对**：交换的终止条件是「值 `v` 已经在下标 `v - 1` 上」，于是结束后凡是 `[1, n]` 内出现过的值都恰好待在自己的下标上（重复值只能占住一个坑，另一个坑留着不合适的值，正好被第一遍扫描发现）。因此第一个「坑位不对」的位置`i` 就是缺失值 `i + 1`。

**为什么是 O(n)**：每次交换都会让一个值落到它的最终位置，此后它不会再被换走；值最多归位 `n` 次，所以内层 while 的总交换次数不超过 `n`，整体是线性的。

## 复杂度

- 时间：O(n)，每个元素最多归位一次，两遍扫描
- 空间：O(1)，除了输入数组本身不再开额外空间（文档里的 Java 解法即是此思路，C++ 里用 `swap` 直接原地换）

## 关键点

- 内层判断必须是 `nums[nums[i] - 1] != nums[i]`：如果只判断 `nums[i] != i + 1`，遇到重复元素会来回死循环
- 越界值（`<= 0` 或 `> n`）直接跳过，不要参与交换
- 交换时先取一个临时变量，或直接用 `std::swap`
- 所有位置都正确时答案是 `n + 1`，别漏掉这个分支
- 元素可能是 `2^31 - 1` 这种大数，好在只有 `[1, n]` 的值会被使用，`int` 足够
