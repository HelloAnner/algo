[思路]
核心矛盾是：哈希表能 O(1) 定位，但记不住「使用顺序」；链表能 O(1) 调整顺序，但定位要 O(n)。把两者拼起来就同时满足：

- 哈希表 key -> 链表节点：O(1) 找到某个 key 对应的节点；
- 双向链表保存所有键值对，头部是最近使用，尾部是最久未使用；调整顺序只需要改几个指针，O(1)。

三个操作：

1. get(key)：哈希表没找到 → 返回 -1；找到 → 把该节点挪到链表头部，返回它的值。
2. put(key, value) 且 key 已存在：改值 + 挪到头部（这算一次使用）。
3. put(key, value) 且 key 不存在：新建节点插到头部并登记哈希表；如果此时 size > capacity，就删掉尾节点，同时用尾节点的 key 去哈希表里删掉那条记录。

为什么对：链表顺序严格对应「最近使用时间」的从新到旧，因此尾部节点的 key 必然是「最久未使用」的那个，淘汰它正好符合 LRU 语义；哈希表与链表在每次操作后保持一一对应，所以定位和改序都不会失效。

C++ 实现上可以用 std::list + unordered_map<int, list<...>::iterator>，也可以像文档里的 Java 版本那样手写双向链表节点（key/val/pre/next）。面试里更推荐手写双向链表 + 哨兵头尾（dummy head/tail），可以省掉一堆空指针判断；本题解用 std::list 的 splice 演示，等价且更短。

[复杂度]
时间：get / put 平均 O(1)（哈希表平均 O(1)，链表插入删除 O(1)）
空间：O(capacity)，链表最多存 capacity 个节点，哈希表同阶

[关键点]
- 删尾节点前先取出它的 key，节点一销毁就没法再反查哈希表了（最容易漏的一步）；
- put 命中已有 key 时也要挪到头部（刷新使用时间），只改值不挪位是错的；
- 用哨兵头尾可以让「链表为空 / 只有一个节点 / 头尾相邻」这些情况不用特判（文档里的 Java 版就是在这些分支上写得很啰嗦）；
- 容量为 1、以及「先 put 后 put 同一个 key」是最容易写错的两个用例；
- 用 std::list 时记得 splice 之后迭代器仍然有效（这正是 splice 比 erase+push_front 好的地方），哈希表里存的迭代器不用更新。

[C++ 代码]
// LRU 缓存
// https://leetcode.cn/problems/lru-cache/
//
// 思路：哈希表（key -> 链表节点）+ 双向链表维护使用顺序，表头是最近使用、表尾是最久未使用。
// 复杂度：时间 O(1)/次操作（平均） 空间 O(capacity)
#include <iostream>
#include <list>
#include <string>
#include <unordered_map>
#include <utility>

using namespace std;

class LRUCache {
  public:
    explicit LRUCache(int capacity) : cap_(capacity) {}

    int get(int key) {
        auto it = pos_.find(key);
        if (it == pos_.end()) return -1;
        // 命中：把节点搬到链表头部（变成最近使用）
        data_.splice(data_.begin(), data_, it->second);
        return it->second->second;
    }

    void put(int key, int value) {
        auto it = pos_.find(key);
        if (it != pos_.end()) {
            // key 已存在：改值 + 刷新为最近使用，不新增条目
            it->second->second = value;
            data_.splice(data_.begin(), data_, it->second);
            return;
        }
        if (static_cast<int>(data_.size()) == cap_) {
            // 先取尾节点的 key，再删节点，最后清哈希表
            int oldKey = data_.back().first;
            data_.pop_back();
            pos_.erase(oldKey);
        }
        data_.emplace_front(key, value);
        pos_[key] = data_.begin();
    }

  private:
    int cap_;
    list<pair<int, int>> data_;                                // front = 最近使用
    unordered_map<int, list<pair<int, int>>::iterator> pos_;   // key -> 对应节点
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int capacity;
    if (!(cin >> capacity)) return 0;
    LRUCache cache(capacity);

    string op;
    while (cin >> op) {
        if (op == "put") {
            int k = 0, v = 0;
            cin >> k >> v;
            cache.put(k, v);
        } else if (op == "get") {
            int k = 0;
            cin >> k;
            cout << cache.get(k) << '\n';
        }
    }
    return 0;
}
