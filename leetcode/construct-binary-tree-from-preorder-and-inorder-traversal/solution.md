## 思路

**方法一：递归（本题 `solution.cpp` 采用）**

前序遍历的第一个元素一定是**根**；在中序遍历里找到这个根的位置 `pos`，则：

- `inorder[inL, pos-1]` 是左子树的中序，长度 `leftLen = pos - inL`；
- `inorder[pos+1, inR]` 是右子树的中序；
- 对应到前序：根之后连续的 `leftLen` 个元素是左子树的前序，即 `[preL+1, preL+leftLen]`，剩下的是右子树的前序 `[preL+leftLen+1, preR]`。

于是递归地「用左子树的前序 + 中序建左子树，用右子树的前序 + 中序建右子树」，就是文档里 Java 方法 1 的做法。

为了不用每次都线性扫描中序，先用哈希表存下「值 → 中序下标」，找根的位置变成 O(1)，整体 O(n)（题目保证值互不相同，所以哈希表不会冲突）。

**方法二：迭代 + 栈（文档里的方法 2）**

用一个栈保存「当前正在走的这条从根出发的路径」，中序指针 `inorderIndex` 指向中序里还没被访问的最左节点：

- 前序每读到一个新值 `preorderVal`，若栈顶的值 != `inorder[inorderIndex]`，说明还没走到最左端，新节点是栈顶的**左孩子**，压栈；
- 否则不断弹栈（每弹一个 `inorderIndex++`），直到栈空或栈顶与中序当前值不同，此时新节点是最后一个被弹出节点的**右孩子**，压栈。

它和前序/中序的定义是对偶的，效果与递归一致，只是把递归栈显式化了。这里按文档保留思路说明，代码用递归版（更好写好讲）。

## 复杂度

- 时间：O(n)。每个节点进递归一次；哈希表让「找根在中序中的位置」是 O(1)（朴素线性查找是 O(n^2)，n = 5000 也能过但不值得）
- 空间：O(n)。哈希表 O(n) + 递归栈 O(h)（最坏退化成链时 h = n），另外存放重建出的树 O(n)

## 关键点

- 递归函数的区间是**闭区间** `[preL, preR]` / `[inL, inR]`，终止条件是 `preL > preR`
- 左子树长度一定要用 `pos - inL` 算，而不是 `pos`（后者在递归到右子树时会错）
- 前序里左子树区间是 `[preL+1, preL+leftLen]`，右子树是 `[preL+leftLen+1, preR]`，两段别写重
- `n = 0` 时直接输出空行，不要访问 `preorder[0]`
- 值为负数时快读/输出都要正常（用 `cin >> int` 即可）
- 重建出的树用「数组池 + 左右孩子下标」表示，避免指针和内存管理；节点下标不会因为 `vector` 扩容而失效
- 题目保证前序与中序**无重复值**，否则哈希表定位根就不成立了
