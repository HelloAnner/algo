## 思路

本质是求这个数字（看成数字字符数组）的**下一个排列**（next permutation），三步走：

1. **从右往左找第一个「升序对」**：找最大的下标 `i` 使得 `a[i-1] < a[i]`（也就是从右往左第一个破坏「非递减」趋势的位置）。如果找不到，说明整个序列从右往左一直非递减，即当前排列已经是最大值，直接返回 `-1`。
2. **在后缀里找最小的、比 `a[i-1]` 大的数字并交换**：后缀 `a[i..]` 一定是**非递增**的，所以从右往左扫，第一个大于 `a[i-1]` 的 `a[j]` 就是后缀里最小的、比 `a[i-1]` 大的元素（`a[j] > a[i-1]` 且 `a[j+1..]` 都 `<= a[i-1]`）。交换 `a[i-1]` 与 `a[j]`。
3. **把后缀反转成非递减**：交换之后 `a[i..]` 仍然是非递增的，把它整体反转就变成非递减，也就是后缀能组成的**最小**排列，这样整体得到的数才最小。

为什么对：

- 要让数变大，必须把某个位置换成更大的数字，最靠右的「可交换位置」`i-1` 保证了变化的高位尽可能低（前缀 `a[0..i-2]` 完全不变，这是所有更大排列里前缀最大的那一类），所以答案是这一类里的最小值；
- 交换时选后缀里**最小的更大者**，保证第 `i-1` 位尽可能小；
- 后缀再排成最小（非递减），使低位尽可能小；
- 三者合起来就是严格大于原数的最小值。

最后把结果字符串转成整数，和 `INT_MAX`（2147483647）比较：超了返回 `-1`。文档里的 Java 版用 `Integer.parseInt` 抛 `NumberFormatException` 来做这件事，C++ 里用 `long long` 承接再比 `INT_MAX` 更直接（注意别直接 `stoi`，它会截断/抛异常）。

## 复杂度

- 时间：O(L)，`L` 是数字的位数（本题最多 10 位），三次线性扫描。
- 空间：O(L)，把数字存成字符串。

## 关键点

- 第 1 步的判断是 `a[i-1] < a[i]`（严格小于）：写反或写成 `<=` 会让含重复数字的答案出错；
- 第 2 步从右往左找第一个 `> a[pivot]` 的元素，别写成找最大值；
- 第 3 步反转的区间是 `[i, L-1]`（即 `pivot + 1` 到末尾），不是整个字符串；
- 结果可能超出 32 位整数（如 `1999999999` → `9199999999`），必须用 `long long` 判断后再决定是否返回 `-1`；
- 只有一位数（如 `5`）时，从右往左找不到升序对，直接 `-1`；
- 数字里含 0 时也成立，例如 `230241` → `230412`。
