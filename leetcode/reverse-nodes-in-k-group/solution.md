## 思路

这道题是「反转链表」的加强版：把链表按 k 个一组切开，每组内部做一次 206 的迭代反转，再按原顺序接回去。

文档里的 Java 解法用的是「哨兵 + 分组截断」：

1. 建哨兵 `dummy`，`dummy.next = head`。`pre` 指向**已翻转部分的尾节点**（初始为 `dummy`），`cur` 指向当前待处理组的第一个节点（初始为 `head`）；
2. 从 `cur` 往后走 k-1 步找到本组尾节点 `tail`。如果中途遇到 `nullptr`，说明剩余节点不足 k 个，**跳出循环、保持原序**；
3. 记下 `nxt = tail->next`（下一组的开头），并把 `tail->next` 置为 `nullptr`，把这一组截断成独立链表；
4. 对这一组做一次完整的迭代反转（复用 206 的三指针写法），把新头接到 `pre->next`；
5. 反转后原来的 `cur` 变成了这一组的**尾**，令 `cur->next = nxt` 把后面的部分接回来；然后 `pre = cur`、`cur = nxt`，继续下一组；
6. 返回 `dummy.next`。

正确性：不变量是「`dummy.next` 到 `pre` 为止的部分已经按题目要求排好，`cur` 是尚未处理的第一个节点」。每轮处理恰好 k 个节点（整组反转后接回），不变量保持；剩余不足 k 个时不再处理，正好满足「保持原有顺序」。

用哨兵节点是为了让**第一组**和后面的组走同一套逻辑，不用特判头节点。

## 复杂度

- 时间：O(n)。每个节点最多被访问两次（一次用于定位组尾，一次用于反转），组数为 n/k，总计仍是线性
- 空间：O(1)，只用常数个指针（递归也可以做，但递归栈是 O(n/k)，面试里更推荐迭代）

## 关键点

- **先判断够不够 k 个，再反转**：不够就整组保持原序，而不是反转完再想办法
- 反转前一定要把 `tail->next` 置空，否则 `reverse` 会一股脑把后面的节点也反转掉
- 反转之后 `cur` 语义变了（从组头变成组尾），必须把之前保存的 `nxt` 接到 `cur->next` 上，链表才不断
- `pre` 更新成 `cur`（新的组尾），而不是新的组头，写错会导致下一组接错位置
- `k = 1` 时每组只有 1 个节点，反转后不变，代码天然正确
- 全程只改 `next` 指针，不改 `val`，满足「必须实际交换节点」的要求
- 本题 ACM 版里，节点内存用 `std::unique_ptr` 池持有，指针操作照常做，但不泄漏
